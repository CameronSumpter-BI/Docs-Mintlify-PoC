The Consumer API gives your application prescription prices for one drug across the pharmacies near a location. You send the drug, a quantity, and where to look, and the API returns each pharmacy with its price.

## What you can build

The Consumer API is designed for user-facing web and mobile apps that help people compare prescription prices [APPROVE V-032]. For example:

- a price-comparison view that lists nearby pharmacies from lowest to highest price;
- a pharmacy finder that shows prices at the pharmacies a user already visits;
- a drug detail page with each form and strength a drug comes in, from the drug dictionary.

## How an integration works

Your server holds your API credentials. It requests an access token, then sends pricing requests on behalf of your app.

## The pricing endpoints

Every pricing endpoint combines one way to identify the drug with one way to find pharmacies:

| Identify the drug by | Near a ZIP code | Near coordinates | At specific pharmacies |
|---|---|---|---|
| NDC (recommended) | `byndc/byzipcode` | `byndc/bylatlong` | `byndc/bypharmacies` |
| Drug form strength ID | `bydfsid/byzipcode` | `bydfsid/bylatlong` | `bydfsid/bypharmacies` |
| Drug name ID | `bydrugnameid/byzipcode` | `bydrugnameid/bylatlong` | `bydrugnameid/bypharmacies` |

Each path starts with `/drugprice/`. [Pricing a Drug](/consumer-api/pricing-a-drug) explains how to choose one.

## Environments

You build and test against a non-production environment that returns synthetic pricing, then move to production when your integration is ready [APPROVE V-015]. See [Getting Access](/get-started/getting-access).

## Security and compliance

Buzz Health is HITRUST i1 certified and has completed a SOC 2 Type II examination [APPROVE V-022]. The API uses bearer tokens over HTTPS, and it's built for server-to-server calls so your credentials never reach a browser.
